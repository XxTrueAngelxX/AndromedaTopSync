# Asgard: подготовка AndromedaTopSync 1.0.0

2026-11-19, подготовлено **без reload/restart**.

Новый JAR размещён в двух местах:

* `/srv/minecraft/servers/asgard/data/plugins/AndromedaTopSync-1.0.0.jar`
* `/srv/minecraft/servers/asgard/data/plugins/update/AndromedaTopSync-1.0.0.jar`

Первая копия необходима для обнаружения нового плагина при следующем запуске;
вторая находится в запрошенной папке обновлений. Только один JAR находится
в активном каталоге, обе копии побайтово одинаковы. Paper заменит его копией
из update при следующем штатном запуске. На работающем сервере плагин ещё
не включён. Время запуска контейнера после подготовки осталось прежним:
`2026-11-19T12:21:57.004099885Z`.

SHA-256 обеих копий совпал с локальным:
`46eb314444ce4cd5876f923fc4781497beb61e2eb60ce0ef6b28f3925505a77c`.

Проверенный backup:
`/srv/minecraft/backups/asgard-top-sync-1.0.0-20261119-183744`.
В нём 480 файлов: оба JAR AJ/DH и полные каталоги этих зависимостей.
Проверены хеши каждого файла; `manifest.json` и `deployment.json` оставлены
на сервере. Каталог backup закрыт правами 0700. Зафиксировано отсутствие
прежнего JAR/каталога TopSync. Конфиги основного сервера не изменялись.

Очередь прежних обновлений сохранена:

* Dialogs 2.0.67: `1535fae8ca0006ca0b44570f539b7da82dce8f5c1db0242cefe214e73271307c`.
* Guilds .37: `8c7ff21292d6f60b2959519516dc6547b95bbe3dc4200f1c8c9f823d08ee1a22`.

Откат до запуска: убрать обе копии TopSync JAR. После запуска: остановить
сервер, убрать TopSync JAR и выполнить штатный запуск. Координатор не пишет
в статистику AJ, поэтому её backup не следует восстанавливать поверх новых
результатов игроков без отдельной причины. YAML DH дополнение не сохраняет.

После будущего рестарта остаётся проверить журнал включения, `/topsync status`
и визуальную синхронизацию игроком. Эта подготовка не является проверкой
работоспособности нового плагина на уже перезапущенном Asgard.
