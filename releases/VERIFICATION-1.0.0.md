# Проверка AndromedaTopSync 1.0.0

Дата: 2026-11-19. Java 25; компиляция Paper API 26.1.2.build.74-stable.

* Штатный `build.ps1`: `mvn clean package`, код 0, 8 JUnit-тестов без ошибок.
* JAR содержит plugin.yml, config.yml и все классы; зависимости не включены.
* Тестовая нода: фактический Paper 26.3-255-c22378f; AJ 2.11.0,
  DecentHolograms 2.10.2, SkinsRestorer 15.12.6. Это проверка установленной ноды;
  базовая целевая платформа проекта остаётся Paper 26.1.2 / Java 25.
* Оба JAR зависимостей побайтово совпали с установленными на Asgard.
* Запуск дошёл до `Done (26.018s)`, координатор включён без ошибки API.
* На тестовой ноде исходно 0 рейтингов AJ и отключённый JAR AJ. Сохранены
  90 файлов в `/srv/minecraft/backups/test-top-sync-20261119-181958`,
  включая каталог AJ и его H2 cache, каталог DH и оба JAR. Использовались
  временные искусственные данные, отдельная табличка/голова и TEXT-дисплей.
* Снимок с Notch: применены имя таблички и профиль головы. После импорта
  более высокого результата jeb_ оба имени сменились на jeb_. Команда
  `/topsync status`: `boards=1, signs=1, preparing=false, error=нет`.
* Отдельный временный диагностический модуль прочитал фактические строки DH
  через его API: `PASS materialized full text: [#1 jeb_: 9.876]`.
  AJ-плейсхолдеры отсутствовали, имя и число соответствовали новому снимку.
* Во время намеренного `ajlb reload` уже начатая подготовка была отклонена
  с `AJ displays changed during preparation`; следующий снимок применился.
  Это ожидаемая защита от изменившегося списка табличек.
* В журнале присутствовал HTTP 429 authlib при разрешении профилей; он
  не помешал последующим подготовленным кадрам. Сетевая недоступность скинов
  остаётся внешним ограничением.

Ручная проверка игроком остаётся обязательной: визуальный переход полного
топ-10, подписи над стендом, таблички и головы; медленная сеть, выгрузка чанка,
несколько зрителей. Серверная проверка без игрока не доказывает одновременную
отрисовку пакетов клиентом. Автотесты проверяют согласованность снимка,
неизменяемость, устаревшую подготовку, предварительную валидацию и обратный
порядок отката после частичного отказа.
