# AndromedaTopSync 1.0.0

Автор: **XxTrueAngelxX**. Дополнение для Paper, которое согласованно обновляет
рейтинги ajLeaderboards: место, имя, значение, табличку, голову лидера и текстовые
дисплеи DecentHolograms. В частности, исправляет преждевременную смену имени над
стендом прыжков относительно остальных элементов рейтинга.

## Как это работает

Для каждого используемого рейтинга выполняется одно чтение строк через API
ajLeaderboards. Из результата создаётся неизменяемый снимок с единым порядком
игроков. До публикации готовятся текстуры всех затронутых голов. Затем в одном
задании основного потока проверяются цели и применяются таблички, головы,
экипировка стоек и строки дисплеев. Ошибка подготовки сохраняет предыдущий кадр;
ошибка применения вызывает обратное применение сохранённых состояний.

Обычный независимый таймер табличек AJ временно отменяется. Сбор статистики AJ
продолжает работать с прежним `stat-refresh`, включая события входа/выхода.
AJ-плейсхолдеры в обслуживаемых дисплеях заменяются значениями одного снимка
**только в памяти**. Остальные плейсхолдеры, оформление, положение и интервалы
дисплеев сохраняются. Фоновый исполнитель новых дисплеев DH на время фиксации
пропускает ход основному потоку: старый асинхронный рендер не обгоняет новый.

Речь о согласованности серверного состояния. Сетевые пакеты разных сущностей
клиент получает последовательно; отображение всех объектов в одном видеокадре
при любой задержке сети гарантировать невозможно.

## Платформа и зависимости

* Paper **26.1.2**, Java **25**, `api-version: '26.1.2'`.
* Обязательно: **ajLeaderboards 2.11.0** и **DecentHolograms 2.10.2**.
  При отсутствии зависимости Paper не загружает дополнение. Другая версия
  отклоняется до перехвата таймеров. Перед обновлением зависимости требуется
  повторная проверка адаптера.
* Необязательно: SkinsRestorer. Читается уже назначенный скин из его API;
  без него используются профили Paper и разрешение профиля через Mojang.
  При недоступной текстуре сохраняется предыдущий полный снимок.
* PlaceholderAPI требуется самому AJ для сбора соответствующей статистики;
  дополнение не регистрирует собственных плейсхолдеров.

Совместимость адаптеров проверяется по точным версиям, поскольку у AJ нет
публичного API приостановки таймера табличек, а у DH — публичной транзакции
рендеринга. Через reflection читаются только `SignManager.updateInterval`,
`DisplayService.renderCoordinator`, `DisplayModule.displayUpdateScheduler` и
`DisplayUpdateScheduler.executor`. Код зависимостей в JAR не включается.
Источники API: [AJ 2.11.0](https://github.com/ajgeiss0702/ajLeaderboards/tree/2.11.0)
и [DH 2.10.2](https://github.com/DecentSoftware-eu/DecentHolograms/tree/2.10.2).

## Команды и настройки

| Команда | Назначение |
| --- | --- |
| `/topsync status` | Текущий снимок, число рейтингов/табличек, подготовка и последняя ошибка |
| `/topsync refresh` | Запросить внеочередную подготовку полного снимка |

Алиасов нет. Право обеих команд и дополнения аргументов:
`andromeda.topsync.admin`, по умолчанию `op`.

Единственный конфиг — `plugins/AndromedaTopSync/config.yml`:

```yaml
config-version: 1
refresh-ticks: 100
prepare-timeout-seconds: 15
skin-cache-seconds: 600
```

`refresh-ticks` — частота проверки уже собранных данных (минимум 20 тиков).
`prepare-timeout-seconds` — предел ожидания данных/профиля (1–60 секунд).
`skin-cache-seconds` — срок повторного использования подготовленной текстуры
(30–3600 секунд). Например, `refresh-ticks: 200` обновляет представление каждые
10 секунд, но не ускоряет получение статистики самим AJ.

Новые отсутствующие параметры добавляются из шаблона с сохранением существующих
и неизвестных значений. В 1.0.0 миграции прежних версий дополнения нет.
Все найденные поддерживаемые рейтинги обслуживаются вместе, поскольку таймер
табличек AJ общий. Список исключений в конфиге не предусмотрен.

## Установка, обновление и откат

1. Сохранить JAR и каталоги `ajLeaderboards`, `DecentHolograms`,
   `AndromedaTopSync`, включая cache AJ, и проверить резервную копию.
2. При первой установке поместить единственный `AndromedaTopSync-1.0.0.jar`
   в `plugins/`. Он включится при следующем штатном запуске. Папка Paper
   `plugins/update/` заменяет существующий JAR и сама по себе не устанавливает
   совершенно новый плагин. Горячая установка в основной сервер не требуется.
3. При последующих обновлениях положить JAR с **точным именем установленного
   файла** в настроенный каталог обновлений Paper. Не оставлять две версии
   плагина в активном каталоге.
4. После запуска проверить журнал до `Done`, `/topsync status`, отсутствие
   ошибок подготовки и одинаковые имя/значение у стенда и полного топа.
5. Для отката остановить сервер и убрать новый JAR либо восстановить прежний.
   При обычном отключении возвращаются исходные шаблоны в памяти и таймер AJ.
   Если DH-конфиги отдельно сохранялись администратором во время работы,
   восстановить их из backup. Дополнение само конфиги DH не сохраняет.

Нельзя выполнять сохранение/массовое пересохранение дисплеев DH в процессе
работы координатора: сторонняя команда сохранит материализованные строки.
Редактирование шаблонов: сначала отключить координатор, затем изменить YAML,
перезагрузить DH и включить координатор. При обычном рестарте YAML остаётся
источником шаблонов. Runtime-данные AJ нельзя заменять ресурсными шаблонами.

## Хранение и ограничения

Истина для статистики — существующее хранилище AJ (H2/SQLite/MySQL согласно
его настройке). Дополнение читает через AJ API, не выполняет прямой SQL,
не меняет Redis, не создаёт собственной БД и не очищает статистику. Снимок,
оригинальные строки и кэш профилей находятся только в RAM. Чтение SkinsRestorer
не меняет назначенные скины. Внешний запрос возможен при разрешении профиля Paper.

Поддерживаются таблички AJ, ближайшие PLAYER_HEAD/PLAYER_WALL_HEAD и стойка
брони по расположению таблички, а также **новые TEXT-дисплеи** DH в `displays/`.
Старый формат `holograms/`, NPC Citizens, другие провайдеры рейтингов и Folia
не обслуживаются. Неоднозначная привязка нескольких стоек или разных лидеров
к одной голове отклоняется, чтобы не менять постороннюю декорацию.
Незагруженные чанки не загружаются принудительно.

Позиции 1–100; типы ALLTIME/HOURLY/DAILY/WEEKLY/MONTHLY/YEARLY.
Имена рейтингов могут содержать подчёркивания. Поддержаны поля `name`,
`displayname`, `prefix`, `suffix`, `value`, `value_raw`, `value_formatted`,
`value_time`, `position`, в прямом `%ajlb_lb_…%` и обёрнутом
`%javascript_ajlbfallback_{ajlb_lb_…}%` виде. Дисплеи с неизвестным полем,
позицией или отсутствующим рейтингом целиком остаются вне обработки.
При равных значениях порядок определяется UUID; все обслуживаемые элементы
используют этот одинаковый порядок. Сохраняется `reverse-sort` AJ и его
форматирование чисел. Пустые позиции показывают `???`.

## Сборка и продолжение разработки

```powershell
./build.ps1
```

Скрипт выполняет `mvn clean package` на Java 25, тесты JUnit и копирует JAR в
`releases/AndromedaTopSync-1.0.0.jar`; если доступен диск E:, также в
`E:\AndromedaDev\Builds\AndromedaTopSync\`. Без E: достаточно `releases/`.

Главный класс — `world.andromeda.topsync.TopSyncPlugin`. При запуске проверяются
зависимости, создаётся фоновый исполнитель подготовки и основной тикер. При
выключении инвалидируются старые задания, завершается исполнитель, возвращаются
шаблоны и таймер AJ (кроме полной остановки сервера).

Начинать изучение с `TopSyncPlugin`, затем `Frame` (снимок и плейсхолдеры),
`Publication` (проверка и откат), `AjAdapter`, `DisplayAdapter` (границы чужих
API), `WorldTargets` (мир) и `Skins` (подготовка текстур). Отдельных listeners,
storage, сетевых ключей или сервисов между нодами нет. JUnit проверяет
неизменяемость, составные плейсхолдеры, устаревшие задания и частичный отказ.

Проверка игроком: поменять порядок двух лидеров прыжков; убедиться, что полное
топ-10, надпись стенда, табличка и голова переходят к новому снимку вместе.
Повторить при медленной загрузке скина, входе/выходе, перезагрузке AJ/DH,
выгрузке/загрузке чанка и рестарте. На задержке подготовки должен целиком
оставаться предыдущий результат. Визуальная проверка клиента обязательна:
компиляция и серверный smoke-тест её не заменяют.

Публикация: отдельная ветка и PR, слияние выполняет владелец. После
подтверждённого слияния — тег `andromeda-top-sync-v1.0.0`, GitHub Release с
JAR и SHA-256. Основные серверы меняются только в явно разрешённой задаче.
